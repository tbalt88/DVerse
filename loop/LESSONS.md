# Burned lessons

Append-only. One entry per lesson that cost real time. EVERY slice spec includes the line "Read loop/LESSONS.md before writing anything"; every executor reads this file at boot. When you burn a new lesson, the grading seat appends it here in the same merge.

Format: what bites, how it was caught, where the mechanical guard lives (or "spec-only" if none).

1. **Windows-only paths in code or tests bite on the Linux runner.** Hardcoded `C:\`, temp dirs outside the repo root, separator-dependent assertions. Three authors hit this independently. Guard: ubuntu CI plus the no-absolute-path leak-scan test (WaveOneIntegrationTests); use `Path.Combine(Path.GetTempPath(), ...)` and repo-relative artifacts always.
2. **`pac solution pack` exit 0 does not mean the artifact is in the zip.** Components silently drop when their path is not individually listed in `solutioncomponents.yml`: FormXml subfolders (4.2), entityrelationships (4.3). Guard: G9 for declared paths; for NEW artifact types, verify presence inside the packed customizations.xml before claiming success.
3. **pack acceptance does not mean import acceptance.** generatedBy must be CrmLive with a version attribute; DisplayMask is PascalCase with the PrimaryName flag; entities need the full platform capability element set. Guard: spec-only plus the golden import step at grading; the seat imports, never the executor.
4. **Microsoft documentation contradicts Microsoft tooling.** solutioncomponents shape (docs list vs real mapping), the obsolete tutorial permission, form element names that do not exist. Guard: decompile-before-parse (ilspycmd against SolutionPackagerLib) and platform-mirror (portal-author a reference, clone it back) are standing procedure; never author from docs alone.
5. **A runtime is present only when it has EXECUTED something.** Get-Command resolves Windows Store stubs for python and node. Guard: spec-only; run `--version` and require exit 0.
6. **Green suites can be structurally blind.** Wave 0's tests passed relative paths so the absolute-path bug could not manifest; unit tests prove the author's expectation, not reality. Guard: integration sweep discovers fixtures from disk; every gate ships a red fixture; mutation-check when strengthening tests (revert the fix, confirm red).
7. **Do not trust stated baselines; measure them.** Wave 1 manifests said "96 tests" when siblings had already moved the number. Guard: spec-only; every executor verifies the baseline in its own worktree before and after.
8. **The rendered UI is a verification rung nothing else covers.** The Matter form imported clean, gates green, and rendered with only an Owner field; every lower rung passed. Guard: spec-only today; drive the running app for any UI-bearing deliverable.
9. **Tests live in a SIBLING project, never nested; no snk files.** The seed repo's two build defects, verified empirically by the 4.4a agent before avoiding them. Guard: G6 discovers and builds every csproj; the layout rule rides in plugin specs.
10. **dotnet test on a non-test library emits no summary at all.** G6 originally read that as build failure. Guard: G6 classifies via IsTestProject (slice G6b); classification failure refuses.
11. **`-getProperty:IsTestProject` without a prior restore reports EMPTY for every project, and the combined `-restore -getProperty` invocation does not fix it.** On a fresh checkout a real test project would silently misclassify as a library, never run its tests, and still Pass: a fail-open trap. Guard: G6 restores then classifies as two separate process invocations; any query failure refuses.
12. **net462 test projects cannot execute on Linux runners; the ladder's environment must match the artifact's TFM.** The first online run after the plugin landed went red on ubuntu because no .NET Framework runtime exists there; the gate refused correctly. Guard: gates-online runs on windows-latest; the ubuntu offline tier remains the cross-platform guard for the harness itself.
13. **G6's real-dotnet fixture tests flake under parallel xUnit execution** (three sightings: two agents and the seat, always passing in isolation). Suspected concurrent dotnet subprocess contention on shared obj state. Open obligation O11; until fixed, a single G6-family failure in a full-suite run that passes in isolation is the known flake, and reruns must be reported as such, never silently retried into green. CLOSED by Slice O11: per-test isolated fixture copies in BuildAndTestsGateTests; suspected-mechanism fix (flake never reproduced in 10 pre-fix runs), five consecutive post-fix suites green.
14. **FormXml `datafieldname` binds by the attribute's lowercase logical name; any other casing makes the control drop SILENTLY at render.** Pack accepted it, import succeeded, publish succeeded, the form editor even showed the rows; the running app rendered only the one control whose datafieldname happened to be lowercase (ownerid). Diagnosed by clone-diff refuting every other hypothesis first (wrong form, dropped rows, stale publish). Another member of the pack-accepts/platform-drops class alongside lesson 2 and 3. Guard: spec-only today; when authoring FormXml, datafieldname must equal the attribute's LogicalName exactly (all lowercase), and any UI-bearing change ends with driving the rendered form (lesson 8).
15. **Plugin registration shapes are import-enforced through SEQUENTIAL rungs, each invisible until the previous one clears, and none catchable by pack.** Live sequence (4.4b grading, commit f203540): a PluginAssembly RootComponent's schemaName must be the assembly FULLNAME, not the short name; the DLL part reference needs a LEADING SLASH (Part URI); a sandbox assembly MUST be strong-named ("Public assembly must have public key token"), so the snk is committed and signing is on (the seed's defect was gitignoring the key, not signing itself); and the PluginType/Step element sets must match the platform's canonical export, which only platform-mirror reveals (register once via Web API, clone back, transcribe). Bonus finding: the canonical step carries PrimaryEntity by logical name and NO SdkMessageFilterId, so declarative steps are org-portable. Guard: platform-mirror is MANDATORY for any new component type's first registration; decompile tells you what pac reads, never what import demands.
16. **The platform's own export can violate our gates' assumptions: G8 refused the canonical id-only RootComponent (type 92 carries no schemaName).** Found because the mirror-transcribed source was gated before import. Guard: G8 accepts id-only entries with an honest skip (slice 4.4c, mutation-checked); when a gate refuses platform-authored output, suspect the gate first.
17. **`pac solution import` leaves plugin steps DISABLED unless `--activate-plugins` is passed; everything else reports success.** Import exit 0, publish clean, step present with correct ids, statecode 1 (disabled): an invalid record sailed through the API right after a "successful" import. Caught only by the mandatory post-import runtime probe (lesson 8's class: green ladder, dead behavior). Guard: every import of a solution carrying steps uses --activate-plugins, and grading includes a negative-input probe against the live org after EVERY import, not just the first registration.
